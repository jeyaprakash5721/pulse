# Pulse

A customer-facing SaaS site for **Pulse**, a fictional real-time business analytics product: a marketing landing page and a live dashboard.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
npm run lint && npm run typecheck && npm run format
```

Requires Node 20.9+.

## Routes

| Route | What |
|---|---|
| `/` | Landing — hero, product showcase, how it works, testimonials, pricing, FAQ, CTA, footer. Fully static. |
| `/dashboard` | KPIs (revenue, users, conversion, orders), revenue / orders / channel charts, transactions table. |
| `GET /api/metrics?range=7d\|30d\|90d\|12m` | KPIs with period-over-period change, bucketed series (day/week/month), channel split. |
| `GET /api/transactions?q=&status=&plan=&sort=&dir=&page=&pageSize=` | Server-side search, filter, sort and pagination. Params are validated and clamped. |

Both APIs add ~300–600 ms latency. Append `?simulate=error` or `?simulate=empty` (or use the *Simulate* control on the dashboard) to see the error and empty states.

## Design decisions

- **Mock data, real API boundary.** Data is generated by a seeded PRNG (`src/lib/data/`), so it is stable across requests and always anchored to today. The UI only talks to it through the route handlers.
- **No chart library.** Charts are hand-written SVG (`src/lib/chart.ts`) — measured at true pixel width so text stays crisp, with hover tooltips and arrow-key inspection on the revenue chart.
- **URL is the state.** Range, search, filters, sort and page live in the query string (shareable, survives reload), updated with the native History API so changing a filter never triggers a page round-trip.
- **No wasted requests.** Search is debounced (300 ms), in-flight requests are aborted when superseded, and responses are cached per URL for the session — paging back or re-selecting a range is instant and free.
- **Stable layout while loading.** First load shows skeletons; subsequent loads keep the previous data on screen (dimmed) instead of collapsing.
- **Performance.** The landing page is static HTML with three tiny client islands (header, pricing toggle). Fonts via `next/font` (self-hosted, no layout shift), no raster images, the LCP headline renders without an entrance animation, and all motion respects `prefers-reduced-motion`.
- **Light and dark** themes follow the OS via CSS variables in `globals.css`.

## Structure

```
src/
  app/              routes, layout, API route handlers
  components/
    landing/        marketing sections
    dashboard/      dashboard, charts, table, loading/empty/error states
    ui/             icons
  lib/
    data/           mock data generators + API helpers (server only)
    query.ts        transactions query parsing (shared client/server)
    use-api.ts      fetch hook: abort, cache, retry
    use-url-state.ts
    chart.ts, format.ts, types.ts, content.ts
```
